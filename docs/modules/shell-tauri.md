# Module: Tauri shell (`src-tauri/`)

## What it does
Starts the app, owns process-wide state and exposes core functions as commands.

```
src-tauri/
├── src/lib.rs            builder, plugins (dialog, opener, single-instance; Android: ytdlp, playback),
│                         command registration, startup tasks (scan defaults, YouTube Music warm-up)
├── src/state.rs          AppState { db, data_dir, scan flags }
├── src/commands/         one file per area; each fn is a #[tauri::command]
│   ├── library.rs        stats, list_tracks/recent/albums/artists, get_track, set_liked, like_youtube, record_play, set_track_kind
│   ├── playlists.rs      list/get/create/rename/delete, add/remove/reorder entries, download_playlist
│   ├── downloads.rs      download queue (pause/resume/retry/remove/clear), storage_info
│   ├── youtube.rs        youtube_search, stream URL (+ prefetch cache), youtube_download/download_track, yt-dlp version/update
│   ├── imports.rs        import_preview (emits import://progress), import_commit, list_import_history
│   ├── playback.rs       Android native player: playback_* commands, clear_stream_cache; re-emits playback://* events
│   ├── scan.rs           folder rules, start/cancel scan (emits scan://progress), last_scan, reclassify_track
│   └── settings.rs       settings map, platform info, list_dirs (in-app folder browser)
├── tauri.conf.json       window, CSP (img-src allows https: for YouTube artwork), asset protocol scope
├── capabilities/         permissions for the main window (core, dialog, opener)
├── icons/                generated by `npx tauri icon` from icons/icon-src.png
└── gen/android/          Android Studio project (see android.md, playback.md)
```

## Conventions
* Commands return `Result<T, String>`; the string is the error shown in a toast.
* Settings keys are constants in the core (`scanner::keys` etc.); commands never invent keys.
* Long work (scans) runs on a thread; async commands use the Tauri runtime.
* Nothing in here should need a unit test: if it does, move the logic to `crates/core`.

## Adding a command
1. Write the function in the right `commands/*.rs` with `#[tauri::command]`.
2. Add it to `generate_handler![…]` in `lib.rs`.
3. Add a one-line wrapper in `src/js/api.js` (`api.xxx`) and a mock case in `mock.js`.

## Build notes
* Desktop (Linux) needs `webkit2gtk-4.1` and `libappindicator-gtk3` from pacman. Without them,
  `cargo check -p offline-player` still works with a stub `pkg-config` first on `PATH` that
  answers every query with success (`cargo check` does not link).
* The registered command list must match `docs/API-v2.md`; the playback commands are registered
  on every platform (desktop stubs answer "native playback is Android-only").
* Android: `npx tauri android build --debug --target aarch64 --apk`. The Rust lib is built as
  `liboffline_player_lib.so` for `arm64-v8a`.
